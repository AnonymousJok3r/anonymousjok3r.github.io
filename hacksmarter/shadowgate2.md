### Bloodhound data

BloodHound analysis revealed a critical Active Directory path leading from **`mitch.r`** to the service account. Specifically, **`mitch.r`** has **`ForceChangePassword`** rights over **`milo`**, allowing an immediate account takeover. From there, **`milo`** holds **`WriteOwner`** permissions on **`mssql_svc`**, permitting an attacker to seize full control of the SQL service account.

### Privilege Escalation&#x20;

Certipy initially failed because secure LDAPS (port 636) was disabled or blocked on the D&#x43;**.** I bypassed this by appending **`-ldap-scheme ldap`** to force plain LDAP (port 389), allowing the authentication bind to succeed.

<figure><img src="../.gitbook/assets/image (464).png" alt=""><figcaption></figcaption></figure>

Using certipy, I discovered that the user sam.h has enrollment rights on a vulnerable certificate template flagged as \[ESC3]. This vulnerability exists because the template has the Certificate Request Agent EKU enabled, allowing user sam.h to enroll in the template and request a certificate on behalf of other domain users like administrator
